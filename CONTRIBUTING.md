# Как участвовать

English version: [CONTRIBUTING.en.md](CONTRIBUTING.en.md).

Спасибо, что хочешь помочь Game of Incidents. Принимаем исправления, улучшения платформы, документацию и **новые сценарии**.

## Лицензии вклада

Код платформы идёт под Apache License 2.0 ([LICENSE](LICENSE)). Сценарии (`scenarios/`) и документация (`docs/`) идут под CC BY 4.0, а скрипты и образы внутри сценариев ещё и под Apache-2.0 ([LICENSE-CONTENT.md](LICENSE-CONTENT.md)). Отправляя pull request, ты соглашаешься на эти лицензии для своего вклада. Подпись `Signed-off-by` не требуется. Не присылай чужой код и тексты без разрешения автора и не включай в вклад секреты и данные реальных систем.

## С чего начать

1. Для крупного изменения сначала открой issue и обсуди идею. Мелкие исправления можно сразу в pull request.
2. Сделай fork, ветку от `main`, внеси изменение небольшими коммитами. Сообщение коммита: тип и область по-английски (`fix(orchestrator): ...`, `feat(web): ...`, `docs: ...`, `test: ...`), тело по существу.
3. Прогони проверки (ниже) и опиши в pull request, что именно проверено.

## Окружение разработки

Нужны Linux (или WSL2/ВМ на Windows и macOS), Node 22, Docker (rootless-демон для песочниц) и GNU Make. Подробности и команды: [README.md](README.md), раздел «Локальная разработка». Платформа без Linux и Docker не запускается, но юнит-тесты для большей части кода работают и без них.

Самый короткий путь поставить платформу целиком на чистый сервер: [docs/runbook-prod-install.md](docs/runbook-prod-install.md), «Быстрый путь» (`scripts/provision/provision.sh`).

## Проверки перед pull request

```bash
npm ci
make typecheck          # типы всех пакетов
make verify             # типы, все тесты с одноразовой PostgreSQL, bash -n и shellcheck (нужен Docker)
```

Если Docker недоступен, запусти хотя бы юнит-тесты:

```bash
npm -w @wom/runtime test && npm -w @wom/scenario test && npm -w @wom/web test && npm -w @wom/orchestrator run test:unit
bash scripts/test/run.sh   # тесты скриптов установки и деплоя
```

Для сценариев: `npx wom scenario lint scenarios/<имя>` и `npx wom scenario test scenarios/<имя>` (нужен Docker; регресс проверяет, что свежий стенд не решён, а эталон решает).

CI в репозитории проверяет pull request по тому же принципу, но без базы данных; решающей проверкой остаётся `make verify`.

## Как добавить сценарий

Сценарий — папка в `scenarios/<slug>/`: `scenario.yaml`, `brief.md`, `debrief.md`, `image/Dockerfile` (или `k8s/`), `break.sh`, `check.sh`, `solve.sh`. Формат: [ADR-0005](docs/adr/0005-scenario-format-v2.md), образец: `scenarios/nginx-502-upstream`. Правила:

- грейдер проверяет **состояние системы**, а не способ решения;
- в сценарии нет реальных компаний, людей, адресов и секретов; пароли учебного стенда вымышленные;
- автор сценария указывается в `NOTICE` (и в разборе, если хочешь); присылая сценарий, ты соглашаешься на CC BY 4.0 и Apache-2.0 для скриптов;
- `wom scenario lint` и `wom scenario test` проходят.

Для генерации папки по описанию инцидента есть инструкция для LLM: `agent-skill/wom-scenario-author/SKILL.md`.

Как отправить сценарий (любой из путей):

- **pull request** с папкой `scenarios/<slug>/` в этот репозиторий — для сценариев в общий каталог; сопровождающий прогонит регресс;
- **кабинет автора** на любой установке платформы («Мои сценарии», zip папки) — модератор той установки проверит и опубликует;
- `wom scenario push scenarios/<slug> --url https://<платформа>` — то же через CLI (логин и пароль в `WOM_USER` и `WOM_PASSWORD`).

Идею без готовой папки можно оставить через шаблон issue «Идея сценария».

## Что важно знать про код

- Имена `wom`, `@wom/*`, `wom_*` и CLI `wom` — исторические внутренние идентификаторы. Продукт называется Game of Incidents; переименование внутренних имён отложено, чтобы не ломать установленные стенды.
- Сообщения интерфейса и документация — на русском; код, имена и коммиты — на английском. Английские версии основных документов приветствуются.
- Платформа запускает недоверенный код. Изменения в изоляции, сетях, правах и грейдере проходят особо внимательный разбор; уязвимости сообщай приватно по [SECURITY.md](SECURITY.md).
