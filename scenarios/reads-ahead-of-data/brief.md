# ALERT: TokenValidation404, доля 404 выше 5 %

Сервер `auth-01`, сервис `tokend`: выдаёт интеграциям клиентов серверные токены и проверяет их при каждом запросе к API. Часть проверок отвечает `404 token not found`, хотя эти токены клиенты получили от нас же.

## Что известно

- `tokend` слушает `127.0.0.1:8080`. `POST /v1/tokens` выдаёт токен на час, `GET /v1/tokens/<токен>` его проверяет. Записи лежат в таблице `install_tokens` базы `tokens`.
- На сервере два кластера MariaDB: старый `db-old` (порт 3306) и новый `db-new` (порт 3307). Команда БД третьи сутки переносит `install_tokens` со старого кластера на новый инструментом `tablemover`. Сегодня ночью у неё плановое окно работ по заявке CHG-4412.
- Большинство запросов проходит. Отказы составляют около 10 % проверок, обычно их нет совсем.
- Релизов `tokend` сегодня не было.

## Что не известно

- Чем токены, которые получают 404, отличаются от остальных.
- Связаны ли отказы с работами команды БД и на каком шаге эти работы сейчас.

## Цель

1. Любой действующий токен проходит проверку с первого запроса и каждый раз, в том числе токен, выданный секунду назад.
2. Перенос таблицы не сорван: `tablemover` работает без ошибок, его очередь изменений сокращается, начинать перенос заново не придётся.
3. Ни один выданный токен не потерян.

## Ограничения

- Данные в обоих кластерах руками не правим: никаких вставок, удалений и правок в `install_tokens` и в служебных таблицах `tablemover`.
- Перенос заново не начинаем: полная копия таблицы занимает больше часа, и всё это время новый кластер неполон. Сервис `tablemover` не останавливаем и на паузу не ставим: завершает перенос команда БД.
- Код в `/opt` только для чтения. Настройки в `/etc` менять можно.
- Плановые задачи других команд не удаляем. Приостановить такую задачу можно, если это нужно для восстановления сервиса.

## Доступ

Пользователь `oncall`, `sudo` без пароля. SQL: `db-old tokens` и `db-new tokens`, один запрос: `db-new tokens -e '<запрос>'`. Перенос: `sudo tablemover status`, справка: `tablemover help`. Сервисы: `sudo service <имя> status|restart` (`tokend`, `tablemover`, `db-old`, `db-new`, `cron`), у `tokend` есть ещё `reload`. Логи в `/var/log/<сервис>/`. Проверить руками:

```bash
curl -s -H 'Content-Type: application/json' -d '{"integration": 7}' localhost:8080/v1/tokens
curl -s localhost:8080/v1/tokens/<токен>
```
