# ALERT: AlertsApiErrors > 50 %

Сервер `alerts-01`, сервис алертов безопасности для репозиториев. Пользователи не могут отклонить или закрыть алерт: больше половины действий заканчиваются ошибкой. Страницы алертов тоже открываются через раз.

## Что известно

- `alerts-api` слушает `127.0.0.1:8080`. Действие пользователя это `POST /alerts/<id>/dismiss`, `/resolve` или `/reopen`. Данные лежат в MariaDB, база `secalerts`.
- Когда выходит бюллетень об уязвимости, `advisory-feed` ставит в очередь Redis по одному заданию на каждый репозиторий, который зависит от уязвимого пакета. Задания выполняет пул воркеров `jobrunner`: проверяет репозиторий и создаёт для него алерт.
- Несколько минут назад вышел бюллетень о библиотеке `lantern-log`. От неё зависят 48 000 репозиториев.
- Около суток назад был бюллетень сравнимого размера, на 31 тысячу репозиториев. Рассылка заняла чуть больше трёх часов, пользователи ничего не заметили.
- Предыдущий дежурный перед уходом перезапустил MariaDB и `jobrunner`. Ошибки вернулись через несколько секунд.
- Релизов `alerts-api` сегодня не было.

## Что не известно

- Что именно мешает действиям пользователей.
- Почему сутки назад бюллетень такого же размера прошёл без последствий.

## Цель

1. Действия пользователей с алертами проходят стабильно уже сейчас, пока бюллетень ещё рассылается.
2. Рассылка бюллетеней продолжается, и ни одно её задание не потеряно: каждый затронутый репозиторий в итоге получит алерт.
3. У базы есть запас: все приложения вместе держат не больше 20 соединений из 40.
4. Следующий большой бюллетень не приводит к тому же.

## Ограничения

- Сервер MariaDB обслуживает команда DBA. Глобальные параметры сервера (`max_connections` и другие) не меняем.
- Очереди нельзя очищать. Задания нельзя удалять или перекладывать в другое место: они остаются в своих очередях, пока не выполнятся.
- Код в `/opt` только для чтения. Имена очередей заданы в коде.
- `advisory-feed` не останавливаем: новые бюллетени должны выходить.
- Сервисы можно перезапускать.

## Доступ

Пользователь `oncall`, `sudo` без пароля. База: `sudo mysql secalerts`. Redis: `redis-cli`. Пул воркеров: `jobrunnerctl --help`, документация в `/usr/share/doc/jobrunner/README`. Сервисы: `sudo service <имя> status|start|stop|restart` (или `systemctl`). Логи в `/var/log/<сервис>/`, журнал изменений хоста в `/var/log/ops/changes.log`. Проверить действие руками:

```bash
curl -s -X POST localhost:8080/alerts/7/dismiss
```
