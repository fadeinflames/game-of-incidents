# 🟠 ALERT: BackupAge > 48h на app-01

**Время:** пятница, 09:15. Ты дежурный. Впереди выходные.

## Что известно

- `app-01` хранит данные приложения в `/srv/app/data`. Каждую ночь в 02:30 cron под пользователем `backup` запускает `/usr/local/bin/backup.sh`: архивирует данные, шифрует ключом из `/etc/backup/` и кладёт результат в `/var/backups/app/`.
- Последний архив в `/var/backups/app/` датирован тремя днями назад. С тех пор ничего нового.
- Три дня назад Security провела «харднинг прав» на сервере. По их словам, «ничего не ломали, только убрали лишние права».
- Cron-job при этом запускается каждую ночь: мониторинг видит запуск, но не видит результат.

## Что не известно

- Что именно поменяла Security.
- Падает ли скрипт целиком или делает пустой архив.

## Цель

Бэкап должен снова работать: запуск под пользователем `backup` завершается успешно и создаёт свежий зашифрованный архив в `/var/backups/app/`.

## Ограничения

- Нельзя отменять харднинг «вообще»: ключ шифрования не должен быть читаем всеми, каталог данных тоже. Security проверит.
- Владельцы остаются прежними: ключ принадлежит `root`, каталог данных — приложению (пользователь `app`), и оно по‑прежнему должно в него писать. Отдать файлы пользователю `backup` — не решение.
- Нельзя запускать бэкап от root: job должен работать под `backup`, как и был задуман.

## Доступ

Shell на `app-01` под пользователем `oncall` с `sudo`. Полезные точки входа:

```bash
tail -n 20 /var/log/backup.log
sudo -u backup /usr/local/bin/backup.sh
id backup; ls -ld /srv/app/data; ls -l /etc/backup/
```
