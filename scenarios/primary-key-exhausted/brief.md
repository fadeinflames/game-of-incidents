# ALERT: TrackerWriteErrors > 90 %

Сервер `app-01`, сервис учёта действий пользователей. Продукт фактически в режиме «только чтение»: всё открывается, но любое новое действие (комментарий, задача, загрузка файла) заканчивается ошибкой.

## Что известно

- `tracker-api` слушает `127.0.0.1:8080`. Каждое действие пользователя это `POST /events`, запись идёт в MariaDB, база `tracker`.
- `GET /events/recent` и `GET /health` отвечают 200.
- Раз в минуту задача `tracker-export` из cron передаёт новые события в аналитику и запоминает, на каком событии остановилась.
- Сегодня днём команда аналитики загрузила в базу историю из старой системы учёта, около 80 тысяч событий. Импорт завершился без ошибок.
- Релизов `tracker-api` сегодня не было. Продукту несколько лет, событий за это время накопилось очень много.

## Что не известно

- Почему запись перестала работать именно сейчас.
- Связан ли с этим сегодняшний импорт.

## Цель

Запись событий снова работает, и при нынешнем росте та же проблема не вернётся ещё много лет: временная отсрочка не считается. Задача выгрузки в аналитику тоже должна работать.

## Ограничения

- Данные не удаляем: ни старые события, ни сегодняшний импорт. Освобождать место под идентификаторы удалением строк нельзя.
- Код в `/opt` только для чтения. Схему базы менять можно.

## Доступ

Пользователь `oncall`, `sudo` без пароля. База: `sudo mysql tracker`. Сервисы: `service <имя> status|start|stop|restart`. Логи: `/var/log/tracker/`. Проверить запись руками:

```bash
curl -s -H 'Content-Type: application/json' -d '{"user_id": 1, "kind": "comment"}' localhost:8080/events
```
