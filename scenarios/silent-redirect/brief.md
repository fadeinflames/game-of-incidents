# 🟡 Жалобы без алертов: вместо сайта города открывается главная

Сервер `front-01`, входная точка сервиса объявлений «Полка». Ты дежурный. Алертов нет, есть обращения в поддержку.

> 🎓 **Учебный кейс.** Если не знаешь, с чего начать, под брифом есть панель «Нужна помощь?»: она открывает этапы диагностики по одному и объясняет, зачем нужна каждая команда. Это бесплатно, как и подсказки 1 и 2. Та же задача без подсказок есть в каталоге под своим обычным названием.

## Что известно

- `nginx` на `front-01` принимает запросы ко всем сайтам сервиса: главный `www.polka.example`, сайты городов вида `ufa.polka.example`, служебные хосты (`api`, `help`, `pay` и другие). Всего около сорока имён. Каждый сайт обслуживает своё приложение на этом же сервере, у каждого свой порт.
- Около девяти часов назад, в окно работ, конфигурацию nginx разложили из одного большого файла по отдельным файлам (заявка OPS-2107). Тогда же завели новый сайт `sale.polka.example`. После работ `nginx -t` прошёл, главная открывалась.
- С тех пор пользователи из Уфы и Воронежа пишут, что вместо сайта своего города попадают на главную.
- Мониторинг молчит: 5xx нет, 4xx в норме.
- DNS на стенде нет. Чтобы спросить nginx про конкретный сайт, передай его имя в заголовке: `curl -i -H 'Host: ufa.polka.example' http://127.0.0.1/`. Приложение каждого сайта подписывает ответ строкой `site=<имя сайта>`.

## Что не известно

- Сколько сайтов затронуто на самом деле. Жалобы пришли на два, остальные никто не проверял.
- Почему мониторинг ничего не заметил.

## Цель

Каждый сайт сервиса отвечает `200`, и ответ даёт его собственное приложение: строка `site=` совпадает с именем, которое спросили.

## Ограничения

- Откат к старому единому файлу не решение: в нём нет сайта `sale.polka.example`, а распродажа начинается на этой неделе.
- Запросы с неизвестным именем по-прежнему уходят на главный сайт: так обрабатываются старые ссылки и опечатки.
- Сайты, выключенные намеренно, остаются выключенными.
- Приложения сайтов лежат в `/opt`, он только для чтения.

## Доступ

Пользователь `oncall`, `sudo` без пароля. Конфигурация в `/etc/nginx`, логи в `/var/log/nginx`. Проверка и применение конфигурации: `sudo nginx -t`, `sudo service nginx reload`.

## Шпаргалка

| Команда | Что показывает |
|---|---|
| `curl -i -H 'Host: <имя>' http://127.0.0.1/` | ответ nginx для конкретного сайта: код, заголовки (`Location` у редиректа), тело |
| `curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: <имя>' http://127.0.0.1/` | только код ответа, удобно в цикле по списку имён |
| `awk '{print $8, $4}' /var/log/nginx/access.log \| sort \| uniq -c` | сколько каких кодов получил каждый сайт |
| `sudo nginx -t` | разбирается ли конфигурация без ошибок |
| `sudo nginx -T` | вся конфигурация, которую nginx читает на самом деле, одним текстом |
| `grep -rn '<текст>' /etc/nginx` | в каком файле и в какой строке встречается текст |
| `find /etc/nginx/sites -type f \| sort` | все файлы сайтов с полными именами |
