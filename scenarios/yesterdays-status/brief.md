# ALERT: поддержка, отказ в платном распознавании после начала периода

Сервер `budget-01`, учёт месячных бюджетов сервиса распознавания документов. Ночью начался новый расчётный период, бюджеты клиентов обнулились. С тех пор в поддержку понемногу пишут клиенты: платное распознавание им недоступно, хотя в новом периоде они ещё ничего не потратили. Большинство клиентов работает как обычно.

## Что известно

- Клиент задаёт месячный бюджет на платное распознавание. Пока расход периода меньше бюджета, шлюзы продукта пропускают платные запросы. Когда бюджет исчерпан, они отказывают до следующего периода.
- Шлюз спрашивает `access-api`: `GET http://127.0.0.1:8080/v1/access/<клиент>`. API отвечает статусом из Redis (ключ `access:<клиент>`), а если статуса там нет, считает его по PostgreSQL: база `budgets`, таблицы `budgets` (лимит) и `usage_current` (расход текущего периода).
- Записи шлюзов об использовании попадают в очередь `queue:budget-updates` в том же Redis. Туда же идут изменения бюджета, которые клиенты делают в личном кабинете. `budget-worker` применяет события из очереди к базе и обновляет статус в Redis.
- Шлюзы на этом сервере изображает сервис `usage-meter`: он шлёт запросы клиентов и досылает записи, которые узлы шлюзов держали в буфере. Запоздавшие записи прошлого периода приходят ещё около суток после сброса, так бывает каждый месяц.
- Настройки сервисов раздаёт `settingsd` (127.0.0.1:8500), его файлы лежат в `/etc/settingsd/namespaces/`.
- Новый период открывает задача `monthly-reset` из cron (`/etc/cron.d/budget-reset`, лог `/var/log/budget-reset/reset.log`). Последний раз она отработала в 00:00 UTC, без ошибок.
- К этому сбросу готовились: неделю назад вышел `budget-worker` 2.8.0, список изменений лежит в `/opt/budget/CHANGELOG`. После сброса релизов не было.
- В том же Redis живут сессии личного кабинета (`session:*`) и счётчики (`meter:seq`, `stats:*`).
- Из обращений: клиенты 1017 и 1042 получают отказ с начала периода. Клиент 1023 поднял бюджет в кабинете больше получаса назад, доступа нет. Клиент 1008 тоже жалуется на отказ.

## Что не известно

- Сколько клиентов получает отказ и что у них общего.
- Откуда берётся отказ, если бюджет в базе не исчерпан.
- Почему изменение бюджета не применяется больше получаса.

## Цель

1. Каждый клиент, чей бюджет текущего периода не исчерпан, получает доступ. Клиенты, которые уже исчерпали новый бюджет, по-прежнему получают отказ.
2. Отказ не возвращается сам: ни через минуту, ни с очередной запоздавшей записью шлюза.
3. Очередь обновлений бюджета разобрана, и ни одно событие из неё не потеряно.
4. `access-api`, `budget-worker` и `usage-meter` работают.

## Ограничения

- Redis общий. Очищать его целиком (`FLUSHALL`, `FLUSHDB`) и удалять очередь нельзя: в её событиях расход клиентов за закрытый период, по которому выставляются счета, и изменения бюджетов.
- Лимиты, расход и расчётные периоды в PostgreSQL руками не правим: это деньги клиентов. Лимит меняет только сам клиент, через очередь.
- Сброс периода выполняется один раз в месяц.
- `usage-meter` изображает шлюзы продукта: его не останавливаем и не перенастраиваем.
- Код в `/opt` только для чтения. Настройки наших сервисов в `/etc` менять можно, перезапускать сервисы тоже.
- Параметры PostgreSQL и Redis принадлежат другой команде.

## Доступ

Пользователь `oncall`, `sudo` без пароля. База: `sudo -u postgres psql -d budgets`. Redis: `redis-cli`. Сервисы: `sudo service <имя> status|start|stop|restart` (или `systemctl`), у `settingsd` есть ещё `reload`. Логи в `/var/log/<сервис>/`.
