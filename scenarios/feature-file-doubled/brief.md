# ALERT: Edge5xxRate > 30 %

Сервер `edge-01`, граница сервиса. Клиенты получают 502, но не постоянно: какое-то время всё работает, потом всё лежит, потом снова работает.

## Что известно

- Запрос идёт так: клиент → `nginx` (порт 80) → воркер `edge-proxy` (127.0.0.1:8081).
- Воркер оценивает каждый запрос модулем защиты от ботов и добавляет в ответ заголовок `X-Bot-Score`. На эту оценку опираются правила клиентов.
- Набор признаков для модуля собирает сервис `featuregen`: раз в 20 секунд он опрашивает один из узлов кластера аналитики (узлы `n1` и `n2`, базы `analytics_n1` и `analytics_n2` в локальном PostgreSQL) и записывает файл `/var/lib/edge/features/current.json`. Прежние версии файла лежат рядом в каталоге `archive`.
- Сегодня идёт плановое изменение доступа в кластере аналитики, заявка SEC-2291. Его выполняет сервис `access-rollout`, узел за узлом.
- Релизов `edge-proxy` и `featuregen` сегодня не было.
- Запросов в логах `nginx` стало заметно больше обычного.

## Что не известно

- Почему воркер то работает, то нет.
- Связан ли рост числа запросов с причиной сбоя или это его следствие.

## Цель

Граница стабильно отвечает 200 и оценивает запросы, а причина устранена так, что сбой не вернётся со следующим циклом генератора.

## Ограничения

- Изменение доступа SEC-2291 обязательно по аудиту: откатывать его и останавливать `access-rollout` нельзя.
- Модуль защиты от ботов должен остаться включённым. Выключить его на время разбирательства можно, оставить выключенным нельзя.
- `featuregen` должен работать: без него набор признаков устаревает.
- Код в `/opt` только для чтения. Настройки сервисов лежат в `/etc`.

## Доступ

Пользователь `oncall`, `sudo` без пароля. База: `sudo -u postgres psql -d analytics_n1`. Сервисы управляются через `service <имя> status|start|stop|restart` (или `systemctl`), логи лежат в `/var/log/<сервис>/`.
