# ALERT: MergeCommitDelay, p95 > 60 с

Сервер хранения `git-03`. Для каждого запроса на слияние здесь создаётся тестовый merge-коммит, с него стартует CI. Сейчас эти коммиты появляются с опозданием на минуту и больше: очередь растёт, потом разбирается пачкой и растёт снова.

## Что известно

- Репозитории лежат в `/var/lib/git/<группа>/<имя>.git`, все bare. Шесть репозиториев с кодом и `studio/assets.git` с исходниками графики студии.
- `gitstored` (127.0.0.1:8075) это сервис хранилища: другие сервисы сами git не запускают, а просят его. Устроен как мастер и один рабочий процесс.
- `mergeq` берёт запросы на слияние из очереди `/var/spool/mergeq/pending`, старые первыми, и просит `gitstored` создать merge-коммит (`refs/merge-requests/<номер>/merge`). Запрос остаётся в очереди, пока коммит не создан.
- Раз в минуту cron запускает `git-housekeeping`: плановое обслуживание тех репозиториев, которым оно пора.
- Разработчики открывают примерно один запрос в две секунды (в стенде их изображает сервис `loadgen`). Обычно merge-коммит появляется меньше чем через секунду.
- Сегодня студия закончила перенос архива исходников графики в `studio/assets.git`. Релизов и изменений настроек на сервере сегодня не было.

## Что не известно

- Почему merge-коммиты создаются волнами и что происходит с сервером между волнами.
- Что изменилось сегодня, если настройки никто не трогал.

## Цель

1. Merge-коммит появляется не позже чем через 10 секунд после запроса, и так постоянно, а не до следующей волны. Проверка наблюдает за сервером до минуты и сама запускает в это время его плановые задачи, поэтому «сейчас тихо» решением не считается.
2. Плановое обслуживание работает как раньше: по расписанию, для всех репозиториев, и для каждого завершается без ошибок.
3. Ни один запрос на слияние не потерян, репозитории целы.

## Ограничения

- Размер сервера фиксирован: 1 CPU и 640 МБ памяти. Добавить ресурсы или вывести сервер из работы нельзя: его репозитории больше нигде не лежат.
- Настройки `gitstored` (`/etc/gitstored/gitstored.conf`) не меняем: они одинаковы на всех серверах хранения. Память, которую не занимает `gitstored`, делят все остальные процессы, поэтому любая фоновая задача на сервере должна укладываться в 150 МБ.
- Обслуживание репозиториев не отключаем, расписание не убираем, репозитории из него не исключаем: без обслуживания они деградируют.
- Данные не удаляем: ни файлы из репозиториев, ни запросы из очереди. Историю репозиториев не переписываем.
- Код в `/opt` и `/usr/local/bin` только для чтения. Настройки в `/etc` и в самих репозиториях менять можно.

## Доступ

Пользователь `oncall`, `sudo` без пароля. Сервисы: `sudo service <имя> status|start|stop|restart` (`gitstored`, `mergeq`, `cron`, `loadgen`). Логи: `/var/log/gitstored/`, `/var/log/mergeq/`, `/var/log/git-housekeeping/`.

```bash
mergeq status                          # очередь и задержки за последние пять минут
curl -s localhost:8075/health          # отвечает ли gitstored
git-housekeeping --plan                # действующие настройки обслуживания и что сделает плановый запуск
sudo -u git git-housekeeping --force web/checkout.git     # обслужить один репозиторий сейчас
sudo -u git git -C /var/lib/git/web/checkout.git log -3   # git в репозиториях запускай от пользователя git
```

Сервер работает в контейнере, поэтому `free` и `top` показывают память и процессоры хост-машины, а не сервера. Счётчики самого сервера лежат в `/sys/fs/cgroup/` (`cpu.stat`, `memory.current`, `memory.max`, `io.stat` и другие). `dmesg` недоступен.
