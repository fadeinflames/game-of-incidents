# Как подступиться

Когда «всё медленно», а деплойменты на вид в порядке, ищи, кто ещё живёт в namespace. Batch‑нагрузка (Job, CronJob) не видна в `get deploy`, но CPU ест точно так же. Порядок действий при шторме всегда один: **остановить генератор → убрать накопившееся → починить причину → включить обратно**.

## Посмотри на namespace целиком

```bash
kubectl -n batch get cronjobs,jobs,pods
```

Обрати внимание на три вещи: колонку `SCHEDULE` у CronJob, список `jobs` с их возрастом (`AGE`) и статусом (`0/1` значит ещё не завершён) и сколько подов экспорта в `Running`. Если job'ы идут с шагом в минуту, а каждый живёт по 15, они не могут не накапливаться.

## Разберись, что именно изменили

```bash
kubectl -n batch get cronjob nightly-export -o yaml
kubectl -n batch logs job/<имя любого job'а> --tail=5
```

В YAML смотри на `spec.schedule`, `spec.concurrencyPolicy` и `spec.suspend`. `concurrencyPolicy: Allow` разрешает запускать новый job, даже если предыдущий ещё работает. Логи job'а скажут, сколько ему ещё осталось: это и есть «длительность экспорта», с которой надо сравнивать расписание.

## Останови генератор новых job'ов

```bash
kubectl -n batch patch cronjob nightly-export -p '{"spec":{"suspend":true}}'
```

`suspend: true` не удаляет CronJob и ничего не ломает: контроллер просто перестаёт создавать новые job'ы по расписанию. Пока он не остановлен, любая уборка бессмысленна: через минуту появится новый job.

## Убери накопившиеся job'ы

```bash
kubectl -n batch delete jobs -l app=nightly-export
kubectl -n batch get pods -l app=nightly-export
```

Удаление job'а удаляет и его под. Подожди, пока поды экспорта исчезнут из списка (несколько секунд на `Terminating`). Один экспорт можно оставить, если он почти закончился, но проще убрать все: он всё равно запустится по расписанию.

## Почини причину и включи экспорт обратно

```bash
kubectl -n batch edit cronjob nightly-export
```

Поставь `concurrencyPolicy: Forbid` (новый job не запускается, пока идёт предыдущий) и разумное расписание: интервал должен быть больше длительности экспорта, а лучше вернуть ночное `0 2 * * *`, пока команда данных не согласует частоту. Затем сними `suspend` (`false`) и проверь `kubectl -n batch get cronjob nightly-export`: `SUSPEND False`, `ACTIVE 0`. После этого жми «Проверить».
