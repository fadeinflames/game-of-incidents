# Architecture Decision Records

Правило проекта: архитектурное решение считается принятым только после того, как ADR переведён в статус **принято** сопровождающим. До этого код, зависящий от решения, не пишется.

У ADR 0003, 0004, 0006, 0008 и 0009 есть разделы «Реализация и отклонения» или «Дополнение» с датой: они описывают, что в коде сделано иначе, чем в первоначальном тексте. При расхождении верить дополнению с более поздней датой, а не первоначальному тексту.

Статусы: `не начат` → `предложено` → `принято` | `отклонено` → `заменено ADR‑NNNN`.

## Шаблон

```markdown
# ADR‑NNNN. Название

- Статус: предложено
- Дата: YYYY‑MM‑DD
- Роли: кто участвовал

## Контекст
## Варианты (таблица: вариант, плюсы, минусы)
## Решение
## Последствия
```
