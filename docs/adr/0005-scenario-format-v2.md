# ADR‑0005. Формат сценария v2

- Статус: **принято** (2026‑09‑29)
- Дата: 2026‑09‑29
- Роли: техлид, автор сценариев, security

## Контекст

Схема v1 текстовых сценариев прежнего проекта (`wom-games`) описывает текстовый сценарий: `title`, `summary`, `type`, `difficulty`, `durationMin`, `contextJson`, `eventsJson`, `hintsJson`, `actionsJson`, `gmScriptJson`. Она хранится в Prisma как JSON‑колонки и импортируется через `POST /api/import` (до 100 сценариев, тело до 1 МБ).

Живой сценарий должен дополнительно описывать **окружение**: образ, скрипты подготовки и поломки, грейдер, эталонное решение, TTL, лимиты, сеть, сервисы, артефакты. Требования брифа: обратная совместимость с v1, версия в схеме, миграция существующих сценариев, локальная проверка одной командой.

Ограничение из ADR‑001 (принято в 7.3): runtime — Docker‑контейнер, поэтому в v2 описывается один контейнер (или compose‑стек из нескольких), а не VM.

## Варианты

### Как хранить окружение

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Всё в одном JSON: скрипты как строки внутри `environment` | Один файл = один сценарий; текущий импорт без изменений транспорта | Bash‑скрипты в JSON‑строках нечитаемы и не редактируются в IDE; нет подсветки, линтеров, тестов |
| B. **Папка сценария** (`scenario.yaml` + `Dockerfile`/`image` + `setup.sh` + `break.sh` + `check.sh` + `solve.sh` + `brief.md` + `debrief.md`), которую CLI **компилирует** в JSON v2 для импорта | Скрипты — нормальные файлы; CI может гонять регресс‑тест; JSON остаётся транспортом для endpoint'а | Нужна CLI (она и так запланирована) |
| C. Папка сценария + отдельный OCI‑образ на каждый сценарий как единственный артефакт | Быстрый старт (всё предсобрано) | Образ не самодостаточен: бриф, подсказки и грейдер всё равно нужны платформе вне образа |

**Выбор: B**, при этом образы всё равно предсобираются (см. `environment.image`), просто источником правды остаётся папка.

### Где живёт секретная часть (grader, solution)

Пользователь — root в песочнице, значит любой файл внутри контейнера он может прочитать. Поэтому `check.sh` и `solve.sh` **не кладутся в образ**: они хранятся в БД платформы и доставляются в песочницу оркестратором только в момент проверки (механизм — ADR‑004). В v2 они — обычные поля, а импорт помечает их как `secret`, и ни один публичный API их не отдаёт (аналогично тому, как `wom-games` уже скрывает `gmScriptJson` от игрока).

## Схема v2 (предложение)

Корень файла импорта: `{ "version": 2, "scenarios": [ ... ] }`. Файл без `version` считается v1.

Сценарий v2 = все поля v1 (без изменений семантики) + новые:

```yaml
# scenario.yaml (авторский формат; CLI собирает из него JSON v2)
version: 2
slug: nginx-502-upstream            # уникальный, [a-z0-9-], ключ для upsert при повторном импорте
title: "Nginx отдаёт 502"
summary: "После ночного деплоя главная страница отвечает 502 Bad Gateway."
type: "nginx, reverse proxy, upstream"
difficulty: JUNIOR
durationMin: 20
tags: [linux, nginx, web]           # новое: для фильтров каталога
contextJson: { ... }                # v1
eventsJson: [ ... ]                 # v1, для leader mode
hintsJson:                          # v1 по форме, но v2 задаёт уровни
  - level: 1, text: "Направление: посмотри, что говорит сам nginx.", penalty: 0
  - level: 2, text: "Инструмент: nginx -t и /var/log/nginx/error.log.", penalty: 5
  - level: 3, text: "Почти ответ: апстрим слушает не тот порт.", penalty: 15
actionsJson: []                     # v1, для leader mode; для живых сценариев может быть пустым
gmScriptJson: null                  # v1

brief: brief.md                     # что видит дежурный: алерт/тикет/жалоба, цель, ограничения
debrief: debrief.md                 # разбор: что было сломано, эталон, ссылки

environment:
  kind: container                   # container | compose; VM-типы появятся с новым RuntimeProvider
  image: ghcr.io/fadeinflames/wom-scenarios/nginx-502:1.0.0   # предсобранный образ
  build: ./image                    # опционально: контекст Dockerfile, из которого CLI собирает image
  setup: setup.sh                   # идемпотентная подготовка (выполняется в образе при сборке или при старте)
  break: break.sh                   # поломка; выполняется при старте сессии, до выдачи терминала
  check: check.sh                   # SECRET; грейдер, stdout = JSON {passed, criteria:[{id,ok,message}]}
  solve: solve.sh                   # SECRET; эталонное решение, используется регресс-тестом и разбором
  ttlMin: 45                        # жёсткий TTL песочницы (>= durationMin)
  resources: { cpus: 1, memoryMb: 512, pids: 256, diskMb: 1024 }
  network: { egress: none }         # none | allowlist: [host:port]
  services:                         # для брифа и health-панели
    - { name: nginx, port: 80, kind: http }
  shell: { user: root, cwd: /root, shell: /bin/bash }
  artifacts:                        # файлы, которые кладутся в песочницу (фейковые логи, графики)
    - { src: artifacts/access.log, dest: /var/log/nginx/access.log }
```

Правила:

- `environment` отсутствует или `null` → сценарий текстовый (leader mode), поведение как в v1.
- Импорт v1‑файла эквивалентен v2 с `environment: null`, `slug` генерируется из `title`.
- `check.sh` возвращает код 0 и JSON в stdout; грейдер проверяет **результат**, а не способ (правило «честной поломки» из брифа).
- Регресс‑тест сценария (CI): свежая песочница + `check` → `passed=false`; свежая песочница + `solve` + `check` → `passed=true`.

## Изменения модели данных (Prisma, черновик)

```prisma
model Scenario {
  // ...поля v1 без изменений...
  schemaVersion   Int      @default(1)
  slug            String?                 // уникален в рамках пака
  tags            String[] @default([])
  briefMd         String?
  debriefMd       String?                 // не отдаётся до завершения сессии
  environmentJson Json?                   // всё из environment, кроме секретных скриптов
  graderScript    String?                 // SECRET: check.sh
  solutionScript  String?                 // SECRET: solve.sh
  @@unique([packId, slug])
}
```

`hintsJson` остаётся JSON, но v2‑валидатор требует `level`/`text`/`penalty`.

## Последствия

- Плюс: все 18 текстовых сценариев `wom-games` импортируются без изменений.
- Плюс: авторский формат — файлы, которые тестируются в CI; JSON — только транспорт.
- Минус: два представления (папка и JSON) требуют CLI; на начальном этапе единственный сценарий будет захардкожен и в CLI не нуждается.
- Минус: секретные поля требуют дисциплины во всех API (нужен единый `sanitizeScenarioForPlayer`, как уже сделано в `wom-games`).

## Принятое решение (2026‑09‑29)

1. Многоконтейнерные сценарии: для MVP достаточно одного контейнера. Схема содержит `kind: container | compose`; на начальном этапе реализуется и валидируется только `container`, `compose` отклоняется линтером с сообщением «не поддерживается в этой версии», чтобы поле было занято и не переименовалось позже.
2. Штрафы за подсказки — **в баллах**: сценарий даёт до 100 баллов, каждая открытая подсказка снимает свой `penalty` (по умолчанию 0 / 5 / 15 для уровней 1 / 2 / 3), время решения хранится отдельно и на баллы не влияет. Формула итогового балла фиксируется позже.

Статус ADR: **принято**.

## Реализация (2026‑09‑30)

- Источник правды схемы — `packages/scenario/src/schema.ts` (zod); `schemas/wom.scenario.v2.json` зеркалит его для внешних валидаторов.
- Добавлено поле `environment.tmpfs: { "/path": "size=160m" }` — единственный честный способ получить «диск заполнен на 100 %» в контейнере (лимит по пути есть только у tmpfs). Tmpfs стартует пустым, поэтому образ должен восстанавливать содержимое в entrypoint (см. `scenarios/disk-full`). Tmpfs учитывается в памяти контейнера — `resources.memoryMb` задаётся с запасом.
- Секретные скрипты (`break`, `check`, `solve`) в БД, в образ не попадают; `environmentJson` в БД хранится без файловых ссылок.
- CLI `wom scenario lint|build|test|run|export`; `test` — регресс из ADR (свежая → `false`, эталон → `true`) плюс пробы харднинга. Песочки CLI помечены `wom.owner=cli`, reconciler оркестратора их не трогает два часа.
- `POST /api/import` принимает v1 (файл `wom-games`, без `version`) и v2 (`wom scenario export`); доступ — роль `admin`.
- Регресс всех сценариев: `make regress` (≈ 10 с на сценарий).

## Дополнение (2026‑09‑30): учебный формат и статус подъёма

Решения: junior‑кейсы в обучающем формате, но разбитые на этапы, которые открываются по запросу игрока, а не стеной текста в брифе; тяжёлые стенды допустимы, если игроку видно, что поднимается и сколько это обычно занимает.

- `guide: guide.md` (необязательно). Markdown делится по заголовкам `## ` на этапы; игрок открывает их по одному кнопкой «Не знаю, что делать» → «Дальше», без штрафа. В БД `Scenario.guideMd`, в UI панель «Нужна помощь?». Линтер: этапов ≥ 1, тег `tutorial` без `guide` — предупреждение.
- `environment.startup: { expectedSec, note }` (необязательно). Обычное время подъёма и пояснение для тяжёлых стендов. Runtime сообщает фазы подъёма (`cluster | images | tools | manifests | sandbox`, оркестратор добавляет `break`) через `SandboxSpec.onProgress`; последняя фаза хранится в `TrainingSession.startupPhase` и показывается на странице сессии вместе с прошедшим временем и обычным ожиданием. В каталоге стенды с `expectedSec ≥ 90` помечены «старт ~N мин».
- Проверка кейса остаётся одной на весь сценарий (пошаговая проверка отклонена).
- **Две копии учебного кейса (решено 2026‑09‑30: обучающая с этапами и обычная для тех, кто уже разбирается).** Папка с `guide.md` импортируется как две записи: `<slug>` (обычная: без guide, бриф без плашки `> 🎓` и секций «Шпаргалка» / «Почитать заранее», штрафы подсказок как в yaml) и `<slug>-tutorial` («<title> · учебный», тег `tutorial`, подсказки 1–2 бесплатно). Скрипты, образ и грейдер общие. Суффикс `-tutorial` зарезервирован линтером. Реализация: `importVariants` в `packages/scenario`, `upsertImportRecord` в `packages/db`.
- **Многонодовые кластеры с метками.** `environment.cluster.nodes` до 4, `environment.cluster.workerLabels` — список меток для воркеров по порядку (зоны `topology.kubernetes.io/zone`, пулы `node-pool`, версии). kind получает их через `labels` в конфиге ноды. Нужны кейсам про drain, зональные диски и межзональную сеть.
- **Публичные образы в `images`.** Сценарий может перечислять готовые образы (PostgreSQL, ingress-nginx, cert-manager, Prometheus, metrics-server, Pebble, VersityGW): демон песочницы вытягивает их при подготовке и грузит в ноду `kind load`. `environment.startup.expectedSec` у таких кейсов 90–200 с, каталог помечает их «старт ~N мин».
